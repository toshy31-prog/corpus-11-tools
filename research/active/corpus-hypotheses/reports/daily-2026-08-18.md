# Rapport quotidien — 2026-08-18

## Changement substantiel

La branche chiralité est close à l'ordre 3 ; factorisation a transporté son reste triple vers `S4` mais échoué au test prospectif H4 ; la priorité a ensuite basculé vers récupération/désinscription, avec une réplication prospective asynchrone multi-port puis un transport vers une event loop réelle horodatée.

## Orientation compositionnelle — fermeture

P1 `too_common`; P2 `not_transported` / `no_predictive_transport`; H3 `standard_absorption`; `I2+A2` suffit à supprimer les résidus P1/P2/joint. Aucun P3 adaptatif.

## Factorisation — transport puis H4 négatif

Le test `S4` a trouvé une clé `(3,3,3)/(2,2,2)` compatible avec dimensions triples `1` et `2` (`transported_remainder`). H4 a ensuite testé 420 extensions par une quatrième matrice : quatre strates appariées, contrastes `+1,0,0,0`, médiane `0`, décision `not_supported`. La droite fixe commune `span((1,1,1,1))` explique le plancher de survie.

## Récupération / désinscription — réplication asynchrone multi-port

### Réplication prospective n=6

Un cas `n=5` a servi uniquement à la conception. La confirmation a été gelée sur une famille distincte `n=6` : DAGs ordonnés à cinq nœuds internes et ports source arbitraires.

Résultats exacts :

- `32768` architectures brutes ;
- `9765` atteignables ;
- `C_info=1` partout ;
- `C_erase_inf=1` partout ;
- `685` strates de contrôle ;
- **176 strates** avec plusieurs valeurs de `C_erase_1` ;
- distribution `C_erase_1` : `1:1`, `2:276`, `3:4824`, `4:4648`, `5:16` ;
- zéro violation de `C_erase_1 = 1 + tau(G_int)`.

Décision : **`replicated_profile_separation`**.

Classification scientifique : **`standard_profile_separation`**.

Le délai/passe bornée ajoute donc une coordonnée opérationnelle au profil, mais cette coordonnée est ici exactement une couverture minimale de sommets.

## Transport vers une event loop réelle

Un second préenregistrement a gelé deux architectures appariées issues du test n=6, un budget de deux resets, une règle de sélection des ports et 120 plans de latence `1..5 ms`, répétés trois fois par architecture.

Banc : tâches `asyncio` distinctes, horodatage `perf_counter_ns()`, analyse selon l'ordre effectivement observé.

### Résultat A

Reset `{0,2}` :

- `360/360` effacements ;
- résidus `{0:360}` ;
- `120` ordres runtime distincts ;
- `0` divergence avec le modèle discret.

Durée médiane observée : `5.554227 ms`.

### Résultat B

Reset `{0,1}` :

- `180/360` effacements ;
- `180/360` échecs ;
- résidus `{0:180,1:180}` ;
- `120` ordres runtime distincts ;
- `0` divergence avec le modèle discret.

Durée médiane observée : `5.536438 ms`.

### Décision

H1 runtime PASS ; H2 cohérence mécaniste PASS (`0/720` divergence).

Classification : **`runtime_transport`**.

La séparation opérationnelle survit donc à une event loop réelle dans cet environnement logiciel. Ce résultat n'est pas matériel et n'ajoute aucun mécanisme au-delà du modèle discret : il transporte seulement l'effet vers un runtime horodaté.

La provenance brute des 720 runs est conservée sous forme JSON gzip/base64 avec hashes SHA-256.

## Prochaine allocation

**Ne pas multiplier les émulations locales.** La prochaine étape utile pour récupération/désinscription doit employer des processus, conteneurs, machines ou composants réellement séparés, avec latences et pertes produites par la pile d'exécution. Le contrat de mesure doit rester gelé : `C_info`, coût à convergence, coût sous deadline, résidus, nombre de ports, messages/opérations et temps.

À défaut d'un tel banc accessible, suspendre la promotion empirique et revenir à la comparaison standard de `F_T` ou au quotient factoriel sans plancher commun.
