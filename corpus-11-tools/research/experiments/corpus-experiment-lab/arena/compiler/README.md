# Capability compiler — minimal executable boundary

This compiler does not translate a Corpus capability into an algorithm. Corpus
capability nodes describe possible analytical behavior and may be unvalidated.

It compiles an explicit domain binding containing:

1. a capability ID and status;
2. a mapping from capability fields to domain observables;
3. a prediction model;
4. an assessment function;
5. a separately named decision extension.

Compilation fails when the decision extension is absent. Every compiled contender
states that its actions depend on that extension and cannot be attributed to the
capability alone.

The first binding maps `CAP.HIDDEN_COST_ASSESSMENT` to Ilyana Sorel's wet-bell
scenario. Several capability fields remain unsupported and are named as such. Its
workshop extension minimizes the next craze increment, then pitch error. That
lexicographic preference is an experimental addition, not a Corpus conclusion.

The second binding maps `CAP.FIELD_CAPACITY_ASSESSMENT` to counterfactual daily air
perturbations. In the first campaign it is Pareto-dominated by the simple `never-wet`
policy and is therefore a pruning candidate, not a success. A proposed
`CAP.REAL_TRANSFORMATION_ASSESSMENT` binding is rejected before execution because
the bell world contains none of its discriminating actors, recourse, workaround,
or reactivation observables.
