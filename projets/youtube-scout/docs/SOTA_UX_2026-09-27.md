# Interface, automatisation et reprise — 27 septembre 2026

## Repères vérifiés

- Recherche et industrie : [Microsoft Research, Guidelines for Human-AI Interaction, CHI 2019](https://www.microsoft.com/en-us/research/project/guidelines-for-human-ai-interaction/). Référence de conception validée en plusieurs étapes, pas record de performance 2026 : expliciter les capacités, les erreurs et les possibilités de correction. Pour Scout, une identité incertaine doit rester corrigeable sans effacer les pistes déjà chargées.
- Accessibilité : [W3C, explication du critère WCAG 2.2 4.1.3](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html). Les mises à jour de statut doivent être exposées aux technologies d'assistance sans déplacement de focus. Le rack utilise déjà `role=status` ; ceci ne constitue pas un audit WCAG complet.
- Open source : [ListenBrainz, API de recommandations](https://listenbrainz.readthedocs.io/en/latest/users/api/recommendation.html). Sépare recommandations par identifiant d'enregistrement et feedback ; API explicitement expérimentale. Réutiliser cette séparation conceptuelle pour garder/rejeter une piste, sans envoyer les goûts ou la bibliothèque de l'utilisateur par défaut. Aucun code copié ni service connecté.
- Industrie musicale récente : [YouTube Music, Explainable Recommendations at Scale, prépublication du 20 septembre 2026](https://arxiv.org/abs/2609.23877). Pré-calcul asynchrone de candidats et justifications ; les auteurs rapportent des essais A/B. Cela suggère de préparer les explications hors du chemin critique. Ce n'est pas une validation indépendante, et une justification générée ne remplace pas une preuve de crédit musical.

## État observable

Les captures montrent deux blocages distincts : des pistes chargées sont masquées par le filtre explicite d'artistes inconnus ; les voies catalogue attendent une identité. Révéler automatiquement les inconnus ou choisir une fiche par simple ressemblance de nom contournerait ces choix, sans corriger l'identification.

Le code avait aussi une incohérence réelle : le bouton d'une voie sélectionnée mais bloquée utilisait `enabled` pour la désélectionner. Or `enabled` est faux tant que l'identité manque : le clic remettait le poids à 1. La correction sépare poids/intention et disponibilité. Le bouton peut désormais désélectionner cette voie ; son `aria-pressed` reflète le choix. L'en-tête distingue directions sélectionnées et disponibles ; « Activer toutes » n'est plus proposé comme remède à une identité manquante lorsque toutes sont déjà sélectionnées.

Fichiers : `public/scout-mixer-panel.mjs`, `public/route-selection-intent.test.mjs`. Sauvegarde : `/tmp/scout-ux-sota-LQPGGu/scout-mixer-panel.mjs`. Aucun rechargement de la page personnelle, aucune recherche externe ni modification des filtres de l'utilisateur.
